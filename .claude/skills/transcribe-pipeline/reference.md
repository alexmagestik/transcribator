# Справка: transcribe-pipeline

## Архитектура

Главный субагент `transcribe-pipeline` запускает **последовательно** трёх
субагентов шагов:

```
source-mp3/*.mp3  →  raw/*.txt  →  clean/*.txt  →  summary/*.md
       ↓                  ↓                 ↓
transcribe-whisper   transcribe-clean   transcribe-summary
(faster-whisper)    (llama3.1-clean)   (gemma4:e2b-32k)
```

## Параллелизация

Сейчас субагенты запускаются **последовательно** (требование пользователя).
В будущем clean и summary будут параллельными — `Agent tool` позволяет
это (запустить несколько `agent()` в одном сообщении).

## Параметры запуска

Каждый субагент принимает от главного:
- `--match "<фрагмент имени>"` — фильтр (для путей с пробелами — обязательно).
- `--force` — флаг перезаписи (если нужно).

Главный субагент сам выбирает, передавать ли `--force`, и какой `--match`.

## Что НЕ делает главный субагент

- Не запускает `transcribe.py` сам — это работа субагентов шагов.
- Не пытается имитировать транскрипт/очистку/саммари.
- Не передаёт субагентам длинные пути с пробелами без `--match`.

## Ошибки

Если субагент вернул ошибку (exit code != 0) — показать её пользователю.
Не запускать следующий шаг, пока текущий не завершился успешно.
